# joewline-blog — інструкція з розгортання

Цей репозиторій — реалізація ТЗ «система публікацій — від нотатки до трьох майданчиків».
Структура:

```
site/     Astro-сайт (те, що бачать читачі) — деплоїться на GitHub Pages
bot/      Cloudflare Worker — приймає нотатки з Telegram, комітить файли в site/
.github/  Автоматична збірка й деплой сайту при кожному push
```

Нижче — послідовність дій від нуля до робочої системи. Кроки 1–4 дають тобі
живий сайт. Кроки 5–11 — робочий Telegram-бот для нотаток. Можна зупинитись
після кроку 4 і писати кейси вручну, а бота підключити пізніше — нічого не
зламається.

---

## Передумови

- Встановлений Node.js (LTS, версія 20+)
- Акаунт GitHub (репозиторій під `floksipet` або окремий — байдуже)
- Акаунт Cloudflare (безкоштовний тариф — цього достатньо)
- Акаунт Telegram

---

## Частина 1 — сайт

### 1. Створи репозиторій на GitHub
Назви його, наприклад, `joewline-blog`. Склонуй собі й поклади в нього всю
структуру з цього комплекту (`site/`, `bot/`, `.github/`, `.gitignore`, цей README).

### 2. Підлаштуй адресу сайту
Відкрий `site/astro.config.mjs` і онови поля `site` та `base` під свій
реальний GitHub-акаунт і назву репозиторію (коментарі у файлі пояснюють обидва
варіанти — з підрепозиторієм чи з власним доменом).

### 3. Постав залежності й перевір локально
```bash
cd site
npm install
npm run dev
```
Відкрий адресу, яку покаже термінал (зазвичай `localhost:4321`) — має
з'явитись сторінка з одним записом «Перший запуск».

Важливо: `npm install` створить файл `package-lock.json` — його потрібно
закомітити разом з іншими файлами, інакше кешування в GitHub Actions (крок 4)
видасть помилку.

### 4. Увімкни GitHub Pages і задеплой
- У репозиторії на GitHub: **Settings → Pages → Source → GitHub Actions**.
- Заштовхни (push) все в гілку `main`.
- У вкладці **Actions** з'явиться прогін `Deploy site` — дочекайся зеленої галочки.
- Сайт буде живий за адресою, яку ти вказав/вказала в `astro.config.mjs`.

Тепер, щоб додати новий запис вручну: скопіюй `site/src/content/cases/_template.md`,
перейменуй, заповни, заповни `status`, зроби `git push` — сайт перебілдиться сам.

## Частина 2 — бот-нотатник у Telegram

### 5. Створи бота
У Telegram напиши **@BotFather** → `/newbot` → дай ім'я → отримаєш
`TELEGRAM_BOT_TOKEN`. Збережи його, знадобиться на кроці 8.

### 6. Створи GitHub-токен для бота
**GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token.**
- Repository access: тільки цей репозиторій (`joewline-blog`).
- Permissions: **Contents → Read and write**, більше нічого не потрібно.
- Збережи токен — це `GITHUB_TOKEN` для бота.

### 7. Встанови Wrangler і увійди в Cloudflare
```bash
cd bot
npm install
npx wrangler login
```
Відкриється браузер для авторизації в Cloudflare.

### 8. Задай секрети воркера
```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET   # придумай будь-який довгий рядок
npx wrangler secret put GITHUB_TOKEN
```
Кожна команда запитає значення в терміналі окремо.

Також відкрий `bot/wrangler.toml` і перевір, що `GITHUB_OWNER`, `GITHUB_REPO`,
`GITHUB_BRANCH` і `CONTENT_PATH` відповідають твоєму реальному репозиторію.

### 9. Задеплой воркера
```bash
npx wrangler deploy
```
У виводі буде адреса виду `https://joewline-intake-bot.<акаунт>.workers.dev` —
вона знадобиться на наступному кроці.

### 10. Зареєструй webhook у Telegram
Заміни `<BOT_TOKEN>`, `<WORKER_URL>` і `<WEBHOOK_SECRET>` на свої значення
(той самий секрет, що й на кроці 8) і виконай:
```bash
curl -X POST "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -d url="<WORKER_URL>" \
  -d secret_token="<WEBHOOK_SECRET>"
```
Відповідь має містити `"ok":true`.

### 11. Перевір увесь ланцюг
Надішли боту голосове або текстове повідомлення. Має статися таке:
1. Бот відповість підтвердженням і шляхом до нового файлу.
2. У репозиторії з'явиться новий коміт з файлом у `site/src/content/cases/`.
3. GitHub Actions автоматично перебілдить і задеплоїть сайт.
4. Новий запис (зі статусом «чернетка») з'явиться на сайті.

## Публікація на DOU і Друкарні

Автоматизації тут немає — API немає в жодної з платформ (детально в ТЗ,
розділ 5). Коли файл дозрів до статусу `done`:
1. Постав `targets: [site, dou]` (або `drukarnia`) у frontmatter.
2. Скопіюй тіло файлу у форму DOU / редактор Друкарні вручну.
3. У DOU обов'язково вкажи посилання на оригінал на своєму сайті як
   канонічне джерело — це офіційно дозволений сценарій крос-посту.

---

## Що можна доробити пізніше (не зараз)

- Увімкнути `announce`-job у `.github/workflows/deploy.yml` для автоанонсів
  у Telegram-канал (зараз вимкнено, `if: false`).
- Кастомний домен замість `github.io`.
- Портфоліо-шар для кейсів зі статусом `done` — окрема тема поза цим ТЗ.
