# Нотатка в joewline-blog з будь-якого проєкту

Це третій вхідний канал системи публікацій (див. `02-tz-sistema-publikaciy.md`
в репозиторії блогу) — на додачу до Telegram-бота. Він комітить напряму в
GitHub через `gh api`, минаючи Telegram повністю. Працює з будь-якого
проєкту/каталогу, бо викликає скрипт за абсолютним шляхом.

Шлях до репозиторію блогу на цій машині:
`/mnt/Edisk/VS CODE FILES/joewline-blog`
(якщо працюєш на іншій машині і цього шляху немає — запитай користувача,
де лежить клон `joewline-blog`, або чи піднімати новий).

## Що робити

1. **Визнач `kind`** з контексту розмови:
   - `case` — якщо йдеться про конкретну проблему з ходом розбору й
     рішенням (навіть неповним), або користувач явно каже "кейс"/"стаття".
   - `thought` — вільна думка/спостереження/статус без чіткої структури
     проблема→рішення. За замовчуванням, якщо не очевидно інше.

2. **Визнач `status`**:
   - `draft` — за замовчуванням, завжди безпечний вибір.
   - `in-progress` — якщо це `case`, який користувач явно описує як "ще в
     роботі".
   - `done` — ТІЛЬКИ якщо користувач явно каже, що це готово/можна
     публікувати як статтю ("готово", "публікуй", "це вже стаття",
     "завершив"). Не вгадуй `done` сам — це видима зміна на сайті (пост
     переїжджає в блок "Завершені статті").

3. **Склади title і body** своїми словами за суттю розмови, стисло,
   від першої особи, у стилі користувача (не формальний переказ). Якщо в
   розмові вже є явні `#теги` — лиши їх у тексті, скрипт сам їх витягне
   й приховає з видимого тексту. Якщо теги очевидні з контексту, але не
   написані — додай через `--tags`.

4. **Виклич скрипт через Bash-tool** (heredoc — щоб не боятись лапок/переносів рядків):

```bash
"/mnt/Edisk/VS CODE FILES/joewline-blog/tools/note.sh" \
  --title "Коротка назва" \
  --kind thought \
  --status draft \
  --tags "тег-проєкту,інший-тег" \
  --body "$(cat <<'NOTE_EOF'
Текст нотатки тут. Можна кілька абзаців.
Можна лишити #хештег прямо в тексті.
NOTE_EOF
)"
```

   Прапорець `--tags` можна опустити, якщо тегів немає чи вони вже є
   в тексті як `#хештег`. Прапорець `--image` (шлях до локального файлу)
   додає фото, якщо воно є під рукою.

5. **Покажи користувачу** те, що вивів скрипт (назва, шлях файлу, теги).
   Сайт перезбереться сам через GitHub Actions за ~30-60с — нічого
   додатково пушити не треба, `gh api` комітить одразу в `main`.

## Обмеження, про яке варто пам'ятати

Пости, створені цим шляхом, **не** анонсуються в Telegram-канал
`@jwl_blog` — анонс туди вміє робити тільки сам бот (в нього є
`TELEGRAM_BOT_TOKEN`, якого тут немає й не повинно бути). Якщо для
користувача важливий анонс саме цього допису — попередь про це коротко;
не блокуй збереження через це.

## Формат, який відтворює скрипт

Ідентичний тому, що пише Telegram-бот (`bot/src/index.js`): той самий
frontmatter (`title/date/status/kind/tags/targets/canonical`), той самий
шаблон `## Проблема / ## Хід розбору / ## Рішення` для `kind: case`, той
самий парсинг `#хештег`. Це навмисно — щоб дописи виглядали однаково
незалежно від каналу, яким прийшли.
